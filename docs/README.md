# OctoAcme Project Management Documentation

## Overview

OctoAcme is a customer-first, iterative project management framework built on principles of clear ownership, data-informed decisions, and psychological safety. This documentation centralizes all process guidance for running projects at OctoAcme.

The OctoAcme framework provides a structured lifecycle for projects—from initial concept validation through execution, release, and continuous improvement. It emphasizes collaboration across functional teams (Product, Engineering, QA), transparent communication, and data-driven decision-making.

## Core Principles

- **Customer-first**: Prioritize customer value and usability in all decisions
- **Iterative delivery**: Deliver small, testable increments to validate assumptions and gather feedback
- **Clear ownership**: Each project has named Product Manager and Project Manager accountable for outcomes
- **Data-informed decisions**: Measure impact, track metrics, and iterate based on evidence
- **Psychological safety**: Encourage feedback, learning, and blameless retrospectives

4. **[Release & Deployment](./octoacme-release-and-deployment.md)** — Pre-release checklists, deployment procedures, smoke testing, rollback plans, and release notes.

5. **[Retrospective & Continuous Improvement](./octoacme-retrospective-and-continuous-improvement.md)** — Capture learnings after sprints/releases, identify action items, and measure improvement impact.

## Key Artifacts

Across the OctoAcme lifecycle, projects maintain several key artifacts:

- **Project Charter / One-pager** — Problem statement, goals, success metrics, stakeholders, timeline
- **Roadmap and Release Plan** — Prioritized backlog, milestones, and timeline
- **Sprint/Iteration Backlog** — Acceptance criteria, estimates, and ownership
- **Risk Register** — Identified risks, impact, likelihood, mitigation plans
- **Retrospective Notes** — Learnings and action items

## Communication Cadence

- **Daily**: Team standups (15 minutes) — progress, blockers, dependencies
- **Weekly**: PM + PdM sync and delivery team standups
- **Weekly**: Risk register review and stakeholder updates
- **Monthly**: Stakeholder briefings and roadmap reviews
- **Ad-hoc**: Escalation and incident communication

## Using These Docs

- Keep the Project Charter and One-pager updated in your project repository
- Link to relevant sections when communicating status or decisions
- Use issue templates (in `.github/ISSUE_TEMPLATE/`) to propose updates to these processes
